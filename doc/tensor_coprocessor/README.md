### Generating descriptor constants / Sinh hằng descriptor

From the repository root, use the [layout map](descriptor_layout.json) and [generator](../../scripts/generate_tensor_descriptor_layout.py):

```text
python scripts/generate_tensor_descriptor_layout.py --format c --output tcop_descriptor_layout.h
python scripts/generate_tensor_descriptor_layout.py --format sv --output tcop_descriptor_layout_pkg.sv
```

Both outputs cover the common header, TREF64, operation config and reference slots, inline LUT locations, instruction/precision selectors, and the OP-009 TLAS header layout. Status constants come directly from the normative HDS table. Offsets are in bytes. Encode multibyte fields explicitly in little endian. Use the ISA companion for mode legality, field values, and buffer validation. The generated constants are shared ABI inputs to driver and RTL implementations. Both generated outputs provide tcop_descriptor_schema_bytes and tcop_descriptor_ref_end, indexed by operation ID and implementation variant. Both functions return zero for an unsupported pair. The [portable C encoder](../../project_support/tensor_coprocessor/tcop_descriptor_encode.h) uses the generated header to initialize a fixed descriptor and write TREF64 records. Add both headers to the C include path. Use generated config offsets with tcop_put_le for operation-specific fields. Use tcop_encode_instruction_word to construct the R-type instruction word for a validated command. It emits rs2=x0 on RV64. Target register setup and instruction issue belong to the driver. The helpers handle wire encoding and basic buffer bounds. Use `tcop_validate_descriptor_header` for host preflight of a complete 64-byte header against the instruction and build selectors. It implements the ISA §10.4 format-before-variant order. The caller checks addressability and body contents separately. TREF writes require the exact initialized schema size and use the generated exclusive reference end. This excludes the inline LUT region even when its offset is 64-byte aligned. The [DMA span helpers](../../project_support/tensor_coprocessor/tcop_dma_span.h) provide checked footprint, half-open range, alignment, address-width, aperture and overlap calculations for preflight. The same header provides `tcop_check_aligned_incr_burst` as a C reference for bus-width, aperture and 4-KiB boundary checks on aligned bursts. Use tcop_check_addressable_dma_range for the local addressability reference and tcop_dma_range_in_aperture for the separate driver policy. The combined tcop_check_dma_range remains available for driver preflight. Use `tcop_check_dma_aliases` after validating all present ranges. Pass the strict read-only disjoint policy for OP-006 and OP-007. The driver still supplies the platform constants, validates mode/precision, reference-specific layout and presence, DMA permissions/contiguity, and manages cache ownership. These helpers do not replace the AXI firewall.

To emit a shared capability table, use the same `--build-profile` JSON input when generating C and SystemVerilog. The tool checks the release-1 structural dependencies and supplied qualified precision subsets. This example represents an INT8 GEMM-only mode-0 build.

```json
{"algorithm_mask":1,"data_precision":0,"control_mode":0,"argmax_impl":0,"xlen":32,"qualified_precision_rows":[1,0,0,0,0,0,0,0,0]}
```

`qualified_precision_rows` follows OP-001 through OP-009. Bits 0, 1 and 2 represent INT8, BF16 and FP16. The generator emits `TCOP_BUILD_OP_001_PRECISION_MASK` through `TCOP_BUILD_OP_009_PRECISION_MASK` and the selected build flags. Provide qualified rows from actual build evidence. Platform identity binding, shape limits and the actual acceptance checks still belong to the integrated build.

The [exact INT8 arithmetic reference](../../project_support/tensor_coprocessor/tcop_requant_reference.py) implements the DEC-054 eight-byte coefficient record, mantissa rounding, signed INT8 requantization and the DEC-065 fused ARGMAX compare domain. It uses rational arithmetic independently of the proposed RTL shift and comparator datapath. Use it to build TEST-036/020 reference vectors.

The [OP-008 sparse reference](../../project_support/tensor_coprocessor/tcop_sparse_reference.py) packs explicitly supplied selector pairs and signed INT8 weights, and validates individual selector tiles for TEST-044. It rejects unselected nonzero weights so it can validate a prepared checkpoint without pruning it. Its sparse_dot helper evaluates a compact column before addends. Feed that accumulator to gemm_int8_epilogue in the requantization reference for addends, rounding, saturation and optional activation. This supplies numerical vectors for TEST-044. Exercise per-tile validation and AXI ordering independently.

The [centered FP32 exp candidate](../../project_support/tensor_coprocessor/tcop_exp_candidate.py) generates a 64-segment coefficient table and evaluates the four-FMA approximation for OP-005, OP-006 and the negative feature-map input of OP-009. The HDS documents its error envelope and the physical qualification still required.

The [FP32 reciprocal candidate](../../project_support/tensor_coprocessor/tcop_reciprocal_candidate.py) uses a 32-entry seed table and two Newton iterations. It models the relative-error budget and subnormal rescale for OP-005, OP-006 and OP-009.

The [OP-006 row reference](../../project_support/tensor_coprocessor/tcop_softmax_reference.py) combines the candidate exp and reciprocal with dense or byte-masked BF16/FP16 inputs, the fixed FP32 sum tree, DEC-070 finite subtraction overflow handling and one final nearest-even conversion. It returns the stored row bits or an OP-006 row fault. Use the model in TEST-041 to check exact bits when RTL uses the same function candidates, and check approximation bounds separately for other implementations.

The [OP-007 row reference](../../project_support/tensor_coprocessor/tcop_layernorm_reference.py) implements the fixed Welford merge tree, correctly rounded division by the row count, epsilon validation, the rsqrt candidate, optional affine processing and the BF16/FP16 output cast. TEST-042 can compare the FP32 statistics before rsqrt for every implementation. Compare full output bits when RTL uses the same rsqrt candidate. Descriptor spans, DMA ordering, fault drain and whole-command output invalidation require command-level checks.

The [OP-005 row reference](../../project_support/tensor_coprocessor/tcop_attention_reference.py) evaluates a single query/head with ordered QK FMA, NONE/CAUSAL/BOOL masking, fixed key-index probability and P×V trees, and the online `m/l/o` recurrence. For TEST-040, match the build's K/V tile width and candidate exp/reciprocal when comparing output bits. The HDS tile-width qualification fixture exercises the online exp cutoff across different tile boundaries.

The [OP-009 sample reference](../../project_support/tensor_coprocessor/tcop_linear_attention_reference.py) runs the causal recurrence for every head of one sample and serializes the TLAS header and FP32 state. Use it in TEST-043 for RESET/CONTINUE bit comparisons with the same exp/reciprocal candidates, checkpoint layout, count validation and the denominator guard. Multiple samples can be compared independently. Use command-level tests for DMA, aperture checks and fault priority across concurrently active contexts.

The [FP32 rsqrt candidate](../../project_support/tensor_coprocessor/tcop_rsqrt_candidate.py) models the OP-007 reciprocal square root for LayerNorm. It uses exponent parity, two small seed banks and two Newton steps across the selected variance-plus-epsilon domain.

The [OP-002 elementwise reference](../../project_support/tensor_coprocessor/tcop_elementwise_reference.py) covers all six modes in INT8, BF16 and FP16. Use it for INT8 rounding, saturation, raw-byte LUT addressing and the SwiGLU LUT/product/requantization order in TEST-038. The floating-point paths use the shared exp/reciprocal candidates for SiLU and GELU_TANH, preserve signed zero, and canonicalize NaN. Compare exact nonlinear result bits only when RTL uses the same candidate arithmetic. Test operand addressing and descriptor validation separately.

The [OP-001 floating-point reference](../../project_support/tensor_coprocessor/tcop_gemm_reference.py) evaluates one output in logical K order, then initial C, bias and residual in order. It returns the output encoding or numerical fault status for TEST-003. Test command-wide error priority and DMA drain separately.

The [OP-004 floating-point reference](../../project_support/tensor_coprocessor/tcop_argmax_reference.py) checks standalone and fused BF16/FP16 ARGMAX. The fused path uses one exact nearest-even binary32 FMA per feature, optional FP32 bias and the pre-output-rounding comparison. Use the INT8 reference for scaled integer scores and drive DMA and CSR errors separately. The floating reference is intended for directed and small randomized vectors. For offline diagnostics, fp_top_two accepts raw BF16/FP16 logit bits or the FP32 bits returned by project_fp32. Use exact_top_two for stored signed INT8 values or the exact scaled scores from Requant8.score. Each helper returns both indices, the exact finite margin when available, and a category for finite scores, NaN, infinity or too few eligible scores.

The [OP-003 numerical reference](../../project_support/tensor_coprocessor/tcop_reduce_reference.py) accepts unsigned storage encodings in logical order and returns the expected GPR bits and status symbol for TEST-039. It implements exact INT8 SUM/MAX and the FP32 fixed tree with integer-based nearest-even rounding. Use separate checks for descriptor acceptance, DMA faults and the CSR fence.

### Summarizing performance traces / Tính KPI từ trace

Run `python scripts/summarize_tensor_trace.py trace.json` on one workload/configuration profile at a time. Use a common capture-relative origin in nanoseconds for all clock domains. Timestamps may be decimal JSON numbers, for example 12.5 for a 2-GHz half-nanosecond edge. Retain the trace resolution until export. The script computes intervals from exact input decimals and formats the output as numeric nanoseconds. The input uses these keys:

```json
{
  "profile": {"workload": "illustrative", "build": "CFG-FULL", "traffic": "idle"},
  "requests": [
    {"id": "req0", "prompt_tokens": 128, "request_ns": 0, "prefill_done_ns": 8000, "token_ns": [9000, 13000, 19000]}
  ],
  "commands": [
    {"id": "hart0:slot2:generation7", "outcome": "success", "accept_ns": 100, "commit_ns": 200, "descriptor_ar_offer_ns": 250, "descriptor_ar_ns": 275, "dispatch_ns": 350, "descriptor_ready_ns": 400, "first_numeric_dma_offer_ns": 425, "result_valid_ns": 700, "result_fire_ns": 750}
  ],
  "handler_events": [{"event_ns": 120, "handler_ns": 900}]
}
```

Use unique command-generation IDs rather than raw CV-X-IF IDs, which can wrap. Complete command outcomes are success/error. Count killed commands and reset-abandoned commands separately without putting them into completion percentiles. For the selected delayed-commit profile, commit_ns must be later than accept_ns. Supply optional descriptor_ar_ns for the first accepted descriptor/header read address. It must follow commit_ns and precede or coincide with subsequently observed validation/result events. Killed commands cannot carry descriptor AR or non-kill commit timestamps. Optional kill_ns records the sampled kill boundary for an accepted killed command and feeds accept_to_kill_ns. Also supply descriptor_ar_offer_ns for the first observed header ARVALID on that owner, including a request still held by ARREADY at the end of a reset-abandoned trace. The offer must follow commit and cannot follow its handshake. The tool reports offer-to-handshake latency when both are available. Optional first_numeric_dma_offer_ns is the first offered numeric operand read or output write for that owner, and requires both dispatch_ns and descriptor_ready_ns. Algorithm-specific gates such as sparse metadata validity still need separate RTL checks. The tool checks only events recorded in the trace. The output uses nearest-rank p50/p95/p99 with sample counts and reports per-request prefill/decode rates. Handler events default to outcome=entered. Record outcome=reset for a selected event abandoned by SoC reset, or outcome=pending if the capture ends before entry. These count in handler_event_outcomes without contributing handler delay samples. On entered events, last_authorized_retire_ns can mark the last retirement of the affected hart's outstanding authorized tensor prefix. When available, first_handler_issue_ns marks the first handler instruction accepted for issue after architectural entry. Omit these optional markers when unobserved or inapplicable. The tool reports prefix retirement, retirement-to-entry and entry-to-first-issue intervals separately. Optional `dispatch_ns` marks scheduler grant of active-command ownership. A post-commit descriptor prefetch before that grant does not mark dispatch. Omit this timestamp if the trace has no grant measurement. Optional descriptor_ready_ns marks successful descriptor validation for a completed command. It can precede or follow dispatch. Omit it if validation failed or the event was not captured. The tool reports commit-to-descriptor-ready and, when both events are present, max(0, ready minus dispatch) as exposed wait and max(0, dispatch minus ready) as readiness ahead of dispatch. The example reports 50 ns of exposed wait. A zero exposed wait does not establish a net latency improvement over prefetch disabled. For a completed mode-2 error, optional `error_visible_ns` marks the first APB-readable coherent error snapshot and `w1c_core_ns` marks its matching clear reaching CLK-CORE. Join both to the command-generation ID. Supply `error_visible_ns` without `w1c_core_ns` if the trace ends before that clear. The tool counts those records separately and leaves them out of completed-clear percentiles. For an ordinary DEC-075 error, optional w1c_host_ns marks the host's matched clear reconciliation. Also supply retire_ns for architectural retirement and id_reusable_ns for release of the protected binding if observed. These fields report core-clear-to-host, error-visible-to-ID-release and retirement-to-ID-release separately. ID release must follow both host reconciliation and retirement. Neither event is required to happen first. Omit unobserved events and use the reported sample counts when comparing captures. Aggregate CV-X-IF metrics remain available, with separate success and error distributions for release reporting. The example above illustrates inputs only. Release limits still require real traces and the signed service assumptions in HDS §13.

Requests default to outcome=success for older traces. Use outcome=error, reset or truncated for an admitted request that did not complete, with an optional reason. Include the prefill completion and ordered delivered token prefix only if observed. The tool reports request_outcomes, incomplete_requests and incomplete_delivered_tokens separately. Successful-delivery TTFT, token-gap percentiles and request_cohort continue to use only successful requests. For batch 4, place the four concurrently scheduled streams from one run in the same input. The cohort prefill rate uses all prompt tokens over the earliest acceptance through the latest prefill completion. The cohort decode rate uses tokens after first delivery per request, over the earliest first to the latest last delivery of streams with two or more tokens. The output uses one wall-clock denominator for the cohort and retains the per-request rates and latency percentiles. Export separate runs when comparing batch sizes or traffic profiles, and report aborted/omitted requests separately. For comparable runs also record cold/warm state, KV starting length, fixture identity, token budgets, arrival schedule and interference as specified in HDS Section 13. The pooled inter-token percentile weights each stream by its count of delivered token gaps.

For optional PE utilization, add an `array_windows` list. For example, a 16×16 single-array dense INT8 window at 1 GHz can use this record.

```json
{"kind":"workload","mode":"dense_int8","arrays":1,"pe_rows":16,"pe_cols":16,"core_cycles":100,"clock_hz":1000000000,"assigned_pe_cycles":19200,"committed_pe_updates":16000}
```

Use `sparse_2of4_int8` for valid paired updates. Label the continuous full-wave window `steady_service` as defined in HDS §13. Export one record per mode and observation window and retain the corresponding run conditions. Count an assigned PE each cycle it owns pending work, including feed or feedback stalls. Count only committed local updates. This example reports 75% assignment coverage, about 83.3% update efficiency within that coverage, and 62.5% total utilization. A sparse record with the same committed-update count reports 32,000 selected slots and the same PE-cycle utilization. These optional summaries are computed from input counters and cannot establish RTL performance independently.

From the repository root, run `python -B scripts/check_tensor_spec.py` with openpyxl installed. It checks maintained local navigation, embedded figure and waveform sources, the active CSR worksheet against its register model, ISA schema sizes and generated constants, and both directions of the HDS requirement-to-test mapping. It also runs directed vectors against the OP-001–009 numerical references, including rounding order, exceptional values, sparse paired-sum width and TLAS checkpoint continuity. The licensed local Arm conversion is optional for this repository check. Run the separate VLSIT HDS checker for template structure and requirements traceability. See HDS §19–20 for the RTL, host and performance verification scope and ownership.

Use `python -B scripts/check_tensor_spec.py --cc gcc` for the native C ABI fixture. It compiles the generated constants and portable C helpers together, checks the common header bytes, TREF64 slots and buffer bounds for all ten schema variants, and compares the complete worked OP-003 descriptor and its RV32/RV64 instruction words against the ISA example. The all-schema TREF64 vectors exercise field packing and reserved byte boundaries. It also checks format-before-variant priority, TREF writes rejected in the LUT region, and an AXI burst ending exactly at the 32-bit address-space boundary. The fixture uses temporary files and checks host encoding, independent of a RISC-V core or RTL simulation.

Add `--verilator <path-to-verilator>` with `g++` on PATH to compile and simulate the generated SystemVerilog ABI package. The fixture checks all exported constants, exact schema lookup for both OP-004 variants, and the literal header, GEMM LUT and TLAS offsets. This exercises the shared package. Decoder behavior still requires RTL integration verification.
