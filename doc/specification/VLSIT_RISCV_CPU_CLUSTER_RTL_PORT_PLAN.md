### 5.2 Tile ownership request/grant

The proposed tile-to-CCU request is a ready/valid channel with the requester hart implicit from the tile instance, a 52-bit cache-line address (`physical_address[55:4]` for the selected `PLEN=56`, 16-byte line), the native 3-bit D-cache request ID, and a request class sufficient to distinguish shared-read, exclusive/write ownership, and eviction/writeback. The CCU returns an accepted ownership grant tied to that request ID and line. The exact request classes and whether refill data shares this channel or stays on the LLC/cache path must be confirmed while mapping HPDcache.

Kênh tile→CCU dự kiến dùng ready/valid, hart ID được suy ra từ instance tile, địa chỉ cache line 52-bit (`physical_address[55:4]` với `PLEN=56` và line 16 byte), request ID D-cache native 3-bit và loại request để phân biệt đọc chia sẻ, xin quyền độc quyền/ghi, và eviction/writeback. CCU trả ownership grant gắn với request ID và line. Cần chốt mã request và việc refill data đi chung kênh hay giữ nguyên đường LLC/cache khi đối chiếu HPDcache.

### 5.3 Tagged two-phase probe

The proposed probe request contains `valid/ready`, transaction tag (`max(1, $clog2(PARA_COH_TXN_NUM))` bits), target hart, 52-bit line address, phase (`PREPARE`, `COMMIT`, or `ABORT`), and target MESI state. The response returns `valid/ready`, the same tag/hart/line identity, observed stable MESI state, completion status, and an owner-writeback-complete indication; it carries no line-data payload. For normal coherence transactions, and CMO operations requiring clean/flush, an M line PREPARE locks the line, waits for same-line miss/refill completion, launches the owner's existing HPDcache flush/writeback path, and responds only after the matching AXI B response. A true CBO.INVAL is the operation-specific exception: it locks/reports the dirty M line without writeback, then invalidates only on COMMIT. A failed B response makes a writeback-required PREPARE fail; the CCU sends ABORT to all prepared targets and does not update the directory or grant the requester. The cache keeps stable M and the line lock through COMMIT/ABORT. COMMIT applies the target state; pre-COMMIT ABORT restores/unlocks without changing stable state. No phase has an ACK timeout. For a missing ACK, the CCU retains the line lock and slot until all expected ACKs or reset; directory and requester grant remain unchanged. See DEC-018, DEC-027–DEC-029, and WF-015–WF-019.

Probe request dự kiến gồm `valid/ready`, transaction tag (`max(1, $clog2(PARA_COH_TXN_NUM))` bit), hart đích, địa chỉ line 52-bit, phase (`PREPARE`, `COMMIT`, `ABORT`) và MESI state đích. Response trả `valid/ready`, cùng nhận dạng tag/hart/line, MESI stable quan sát được, completion status và cờ owner-writeback-done; không có payload line. Với coherence transaction thông thường và CMO cần clean/flush, PREPARE của line M khóa line, chờ miss/refill cùng line hoàn tất, yêu cầu HPDcache owner writeback qua AXI hiện có và chỉ response sau B response tương ứng. CBO.INVAL thật là ngoại lệ theo operation: PREPARE chỉ khóa/báo line M dirty, không writeback; line chỉ invalidate tại COMMIT. Nếu B response lỗi trong PREPARE cần writeback, CCU gửi ABORT tới mọi target đã prepare, không cập nhật directory và không cấp requester. Cache giữ M và line lock đến COMMIT/ABORT. COMMIT áp dụng state đích; ABORT trước COMMIT giữ state cũ rồi nhả lock. Không phase nào có timeout ACK. Khi thiếu ACK, CCU giữ line lock/slot đến khi nhận đủ response hoặc reset; directory và requester grant không đổi. Xem DEC-018, DEC-027–DEC-029 và WF-015–WF-019.

### 5.4 Directory and LLC

Directory line mapping uses `line_addr[1:0]` as the bank number (physical address `[5:4]` for a 16-byte line). The standalone directory exposes one indexed request lane per bank and does not select among transaction slots; `m_vlsit_riscv_coh_bank_arb` performs per-bank round-robin selection before driving those lanes. It holds each bank's grant stable until acceptance, advances priority after that handshake, and allows independent banks to grant concurrently. Each set uses seven-bit tree-PLRU initialized to zero and chooses an invalid way before PLRU replacement. A miss reserves its set by transaction tag; same-set lookups wait until a matching update or cancel, while other sets can proceed. A full set returns its victim metadata so the CCU can invalidate holders and resolve dirty data before replacement. Directory state updates follow cache COMMIT acknowledgements. CBO maintenance shares the CCU line lock and transaction context; the LLC operation remains a separate per-line no-refill service ordered with CPU LLC traffic. The LLC AXI data path is 64-bit and its cache line is 128-bit (two beats). Exact SRAM macro ports, ECC/parity, and `axi_llc` service-port mapping remain integration items.

Địa chỉ bank của directory lấy từ `line_addr[1:0]` (tương ứng physical address `[5:4]` khi line 16 byte). Directory độc lập có một lane request cố định cho mỗi bank và không tự chọn transaction slot; CCU phải round-robin các slot đủ điều kiện trước khi drive lane. Mỗi set dùng tree-PLRU 7 bit khởi tạo bằng 0 và ưu tiên way invalid. Miss reserve set theo transaction tag; lookup cùng set chờ update/cancel khớp, còn set khác vẫn có thể chạy. Khi set đầy, directory trả metadata victim để CCU invalidate holder và xử lý dirty data trước khi thay. Chỉ cập nhật directory sau COMMIT ACK từ cache. Bảo trì CBO dùng chung line lock/context CCU; thao tác LLC từng line không refill là dịch vụ riêng, phải được xếp thứ tự với CPU traffic. AXI LLC rộng 64 bit, line 128 bit (hai beat). Port SRAM macro, ECC/parity và mapping service port của `axi_llc` vẫn là đầu vào tích hợp.
Địa chỉ bank của directory lấy từ `line_addr[1:0]` (tương ứng physical address `[5:4]` khi line 16 byte). ### 5.7 HPDcache MESI source impact / Ảnh hưởng MESI lên source HPDcache

The selected CVA6 configuration builds HPDcache with a 64-bit request/access word and a 128-bit cache line. A full dirty-line intervention therefore needs two 64-bit cache-array reads before the 128-bit line response is complete. The HPDcache tag directory and data array are accessed through shared single-request RAM control paths; the source does not expose an independent probe port. The implementation must arbitrate probe tag/data access against CPU, refill, flush, and error-correction accesses. A probe can therefore delay a CPU hit while it owns a needed RAM port. Other-address requests remain eligible only when those local ports, the four load MSHRs, CCU slots, and downstream resources permit; the spec must not promise zero-cycle or uninterrupted hit service during a probe.

The source declares `hpdcache_dir_entry_t` locally in `hpdcache.sv`, with `valid`, `wback`, `dirty`, `fetch`, and `tag`. The minimum explicit stable MESI encoding for the selected write-back cache adds one `exclusive` metadata bit: Invalid=`valid=0`; Shared=`valid=1, dirty=0, exclusive=0`; Exclusive=`valid=1, dirty=0, exclusive=1`; Modified=`valid=1, dirty=1, exclusive=0`. `fetch` remains a transient refill marker. Every refill, normal directory update, CMO update, and error-recovery construction must define the new bit. This increases each L1 directory entry by one bit; it does not require changing `hpdcache_pkg.sv`.

The modified HPDcache controller also exports valid-qualified Stage-1 observation lines: `(coh_access_line_valid_o, coh_access_nline_o)` identifies the active Stage-1 CPU request, and `(coh_victim_line_valid_o, coh_victim_nline_o)` identifies the selected replacement victim. These observations propagate through the HPDcache top, CVA6 cache wrapper/subsystem, CVA6 tile port, and 2/4-hart tile array. The valid bits prevent an inactive zero address from aliasing a real lock on physical line zero. These status observations do not implement exclusion: the per-tag lock vector is still applied in HPDcache, and the exact-line busy query still gates PREPARE until admitted same-line work drains.

HPDcache controller modification, 2026-11-15: exported valid-qualified Stage-1 access and selected-victim line observations; propagated them to the CPU tile array; added valid gating to lock-observation outputs. This closes the tile-array's former dependence on unprovided external address inputs. The change does not replace native HPDcache lock-vector enforcement or probe-busy admission.

### 5.8 Selected dirty-owner writeback path / Đường writeback dirty-owner đã chọn

**Selected contract — Option A.** During PREPARE of an M line, the owner D-cache retains stable M and the line lock, resolves the line's set/way, and requests a probe-originated operation from its existing HPDcache flush engine. The engine reads the full 16-byte line as two 64-bit words and writes it through that hart's existing AXI path to the LLC. The cache reports PREPARE completion only after the matching AXI B response. The response contains `(tag, hart, line, observed MESI, status, writeback_done)` and no line-data payload. A failed B response marks PREPARE failed; the CCU sends ABORT to all prepared targets and leaves directory state and requester grant unchanged. Successful PREPARE permits COMMIT; the cache changes M→S or M→I only on COMMIT and releases the line lock only after COMMIT/ABORT.

The existing `hpdcache_flush` engine is reusable for the data read/write sequencing, but its current source audit shows only normal-control and CMO allocation sources, a shared ACK output, and no probe-specific B-error status output. The modified copy therefore adds a third probe source to the allocator, records each flush origin with the line in its response directory, and routes completion/error back only to that source. This prevents a probe B response from being mistaken for a normal flush/CMO completion. The cache controller holds the matching probe tag and line while the writeback is active. No new CCU AXI master, LLC mux input, external AXI ID bit, or top-level memory port is added; the approved seven-bit external memory ID remains unchanged.

Performance and recovery consequences: PREPARE for M cannot complete until both 64-bit data beats and the matching B response finish. Any AXI/LLC backpressure extends the line lock and transaction occupancy without a timeout. On B error, the owner keeps M as the authoritative copy, reports a failed PREPARE, and waits for ABORT before releasing its local lock; no requester is granted. On successful B response, the LLC is current while the owner still holds M, so data access remains blocked by the line lock until COMMIT/ABORT. Same-bank, same-cache-array, flush-engine, and AXI contention can delay unrelated requests; they may continue only when those resources are independent.

**Đã chọn — Phương án A.** Khi PREPARE gặp line M, D-cache owner giữ stable M và line lock, tìm set/way của line rồi yêu cầu flush engine HPDcache hiện có thực hiện writeback do probe khởi phát. Engine đọc đủ line 16 byte thành hai word 64-bit và ghi qua AXI path hiện có của hart tới LLC. Cache chỉ báo PREPARE hoàn tất sau AXI B response khớp. Response gồm `(tag, hart, line, MESI đã quan sát, status, writeback_done)`, không mang payload dữ liệu line. Nếu B response lỗi, PREPARE thất bại; CCU gửi ABORT tới mọi target đã prepare và không đổi directory/không cấp requester. PREPARE thành công mới cho phép COMMIT; cache chỉ đổi M→S hoặc M→I khi COMMIT và chỉ nhả line lock sau COMMIT/ABORT.

`hpdcache_flush` hiện có thể tái sử dụng phần tuần tự đọc/ghi dữ liệu, nhưng source audit cho thấy allocator hiện chỉ có nguồn normal-control và CMO, ACK dùng chung, chưa có status lỗi B dành cho probe. Bản sao được sửa phải thêm nguồn probe thứ ba, lưu nguồn khởi phát cùng line trong response directory, rồi chỉ route completion/error về đúng nguồn. Như vậy B response của probe không bị nhầm thành completion của flush/CMO thông thường. Cache controller giữ tag và line của probe tương ứng khi writeback đang chạy. Không thêm CCU AXI master, ngõ vào mux LLC, bit memory ID ngoài hoặc port bộ nhớ top-level; memory ID ngoài 7 bit đã duyệt được giữ nguyên.

Hệ quả hiệu năng và recovery: PREPARE của M chờ đủ hai beat 64-bit và B response đúng giao dịch. Backpressure AXI/LLC kéo dài line lock và transaction occupancy, không timeout. Nếu B lỗi, owner giữ M là bản dữ liệu có thẩm quyền, báo PREPARE lỗi và chờ ABORT mới nhả lock cục bộ; không cấp requester. Sau B thành công, LLC hiện hành trong khi owner vẫn giữ M; truy cập dữ liệu line bị khóa đến COMMIT/ABORT. Tranh chấp cùng bank, cache array, flush engine hoặc AXI có thể làm chậm request khác; request chỉ tiếp tục khi tài nguyên tương ứng độc lập.

### 5.9 CBO/CMO maintenance and precise retirement / Bảo trì CBO/CMO và nghỉ hưu chính xác

The new `m_vlsit_riscv_cmo_controller` is a VLSIT block. It accepts a legal operation after CVA6 privilege/CBIE decode, the translated physical line address, and retained architectural context needed for an exception (original effective address and instruction PC). Exact packed fields and the CVA6 cut point remain to be frozen with the complete module port table. There are no new external cluster ports.

The CMO controller allocates a context from the existing `m_vlsit_riscv_coh_txn_table`, obtains the shared CCU line lock, and targets only directory-recorded L1 holders. PREPARE depends on the resolved operation: for CLEAN, FLUSH, and CBIE-decoded INVAL-as-FLUSH, an M holder writes back through the existing HPDcache path and waits for its matching B response while retaining M; for true INVAL, PREPARE only locks and records the holder, with no writeback. After all PREPARE responses succeed, the controller issues the per-line LLC operation. CLEAN retains cache copies and transitions the successful sole M owner to E; FLUSH invalidates L1 and LLC copies only after clean-to-memory succeeds; true INVAL discards L1/LLC copies without writeback at commit; CBIE-decoded INVAL-as-FLUSH follows FLUSH. LLC CMO misses do not allocate or refill. Same-line CPU/LLC operations remain blocked until commit/abort; unrelated work proceeds only when shared banks, ports, MSHRs, and transaction contexts permit.

If a writeback-required operation encounters an owner or LLC writeback error, the controller preserves the dirty source and all stable MESI/directory state, sends ABORT to every prepared holder, waits for all required ACKs with no timeout, then returns the error to CVA6. The modified CVA6 commit path keeps the CBO at the retirement head and blocks younger retirement until completion. It retires once on success; after failed CMO rollback completes, it raises a precise synchronous Store/AMO access fault (exception code 7) before retirement, with the original instruction PC in `mepc`/`sepc` and original effective address in `mtval`/`stval`. This is the selected cluster policy for a CMO writeback error; it does not imply that the RISC-V CMO specification mandates this internal bus-error mapping. True INVAL issues no writeback and has no writeback B-error path. A request grant is not completion.

Pinned-source findings require licensed CVA6 copies of `core/commit_stage.sv`, `core/store_unit.sv`, `core/store_buffer.sv`, `core/cache_subsystem/cva6_hpdcache_if_adapter.sv`, and the routing files listed in Section 4. The current `cva6_hpdcache_if_adapter.sv` maps CBO operations to local HPDcache CMO commands, so that path must be intercepted; it must not bypass the cluster directory. The store buffer waits for `data_rvalid` but does not carry a writeback error to retirement. Exact source cut points and any further transitive files must be confirmed before the source-copy list is frozen. Keep original license notices and add the required modification history to each copied file.

The pinned PULP LLC does not expose the required per-line no-refill CMO service. Its licensed copy must add a maintenance descriptor, same-line arbitration with CPU descriptors, commit-gated tag/dirty state updates, and propagation of the matching memory B response for CBO CLEAN/FLUSH. Source candidates are `axi_llc_pkg.sv`, `axi_llc_top.sv`, `axi_llc_hit_miss.sv`, `hit_miss_detect/axi_llc_tag_store.sv`, `eviction_refill/axi_llc_w_master.sv`, plus transitive descriptor/arbiter modules found during the source walk. On B error, do not invalidate the tag or clear dirty; preserve the current line data and return error to the CMO context. FENCE.I does not issue this LLC-to-memory maintenance operation; it only requires the dirty line to be accepted into LLC. The exact additional file list remains a plan-review item. Keep `rtl/common/third_party` pristine.

FENCE.I uses the selected `DcacheFlushOnFenceI=1` whole-D-cache walk. Each dirty M line is written from the owner to shared LLC through the CCU/HPDcache AXI path; after the successful LLC-acceptance B response, the owner may transition M→E and the directory remains a holder. The walk does not request LLC-to-DRAM writeback. When the walk completes, invalidate the executing hart's local I-cache and fetch pipeline, then complete the fence. A non-OKAY L1-to-LLC response preserves the dirty M line and directory holder, triggers ABORT, and waits for every required ABORT ACK. After ABORT completes, CVA6 raises a precise synchronous custom exception (cause 24) at the FENCE.I PC and places the aligned physical line base in `mtval`/`stval`; the fence and younger instructions do not retire, and local I-cache/fetch invalidation is suppressed. Implement and verify the trap path and retry behavior under DEP-021. This is a local instruction-stream operation; other harts require their own software-notified FENCE.I.

`m_vlsit_riscv_cmo_controller` dự kiến là khối VLSIT mới. Khối nhận operation hợp lệ sau khi CVA6 giải mã privilege/CBIE, địa chỉ line vật lý đã dịch và ngữ cảnh kiến trúc cần cho exception (địa chỉ hiệu dụng gốc và PC lệnh). Field packed và điểm tách khỏi CVA6 sẽ được chốt cùng bảng port module đầy đủ. Không thêm external cluster port.

CMO controller lấy context từ `m_vlsit_riscv_coh_txn_table` hiện có, dùng CCU line lock chung và chỉ gửi tới L1 holder có trong directory. PREPARE phụ thuộc operation đã giải mã: CLEAN, FLUSH và INVAL bị CBIE đổi thành FLUSH sẽ writeback holder M qua HPDcache hiện có, chờ đúng B response và giữ M; INVAL thật chỉ khóa line và ghi nhận holder, không writeback. Sau khi đủ PREPARE thành công, controller yêu cầu LLC thao tác từng line. CLEAN giữ các cache copy và đổi owner M duy nhất thành E sau khi thành công; FLUSH chỉ invalidate copy L1/LLC sau khi clean-to-memory thành công; INVAL thật bỏ copy L1/LLC không writeback tại commit; INVAL bị CBIE đổi thành FLUSH sẽ theo FLUSH. CMO miss ở LLC không cấp phát hoặc refill. CPU/LLC thao tác cùng line bị chặn đến commit/abort; công việc line khác chỉ chạy nếu bank, port, MSHR và context còn tài nguyên.

Nếu operation bắt buộc writeback mà owner hoặc LLC báo lỗi, controller giữ nguồn dữ liệu dirty cùng mọi stable MESI/directory state, gửi ABORT tới mọi holder đã PREPARE, đợi đủ ACK theo chính sách không timeout rồi mới trả lỗi về CVA6. CVA6 commit path được sửa để giữ CBO ở đầu hàng retirement và chặn lệnh trẻ hơn đến khi hoàn tất. Thành công thì retire đúng một lần; sau rollback CMO lỗi, phát Store/AMO access fault đồng bộ chính xác (exception code 7) trước retire, ghi PC gốc vào `mepc`/`sepc` và địa chỉ hiệu dụng gốc vào `mtval`/`stval`. Đây là chính sách cluster đã chọn cho lỗi writeback CMO; không có nghĩa đặc tả RISC-V CMO bắt buộc ánh xạ lỗi bus nội bộ theo cách này. INVAL thật không writeback nên không có writeback B-error. Request grant không phải completion.

Source đã pin cho thấy cần bản sao CVA6 có license của `core/commit_stage.sv`, `core/store_unit.sv`, `core/store_buffer.sv`, `core/cache_subsystem/cva6_hpdcache_if_adapter.sv` và các file định tuyến ở Mục 4. `cva6_hpdcache_if_adapter.sv` hiện ánh xạ CBO thành lệnh CMO local của HPDcache nên phải chặn đường đó; không được bỏ qua directory cluster. Store buffer chờ `data_rvalid` nhưng chưa chuyển writeback error tới retirement. Cần chốt điểm nối chính xác và file phụ thuộc trước khi khóa source-copy list. Giữ license gốc và thêm history sửa đổi bắt buộc cho mỗi file sao chép.

PULP LLC đã pin chưa có dịch vụ CMO từng line không refill. Bản sao có license cần thêm descriptor bảo trì, phân xử cùng line với CPU descriptor, cập nhật tag/dirty theo commit và chuyển status B tương ứng. Các source ứng viên gồm `axi_llc_pkg.sv`, `axi_llc_top.sv`, `axi_llc_hit_miss.sv`, `hit_miss_detect/axi_llc_tag_store.sv`, `eviction_refill/axi_llc_w_master.sv` cùng module descriptor/arbitration phụ thuộc được tìm trong source walk. Khi B lỗi, không invalidate tag hay clear dirty; giữ data line hiện tại và trả lỗi về CMO context. Danh sách file phụ thuộc bổ sung cần review. Giữ nguyên `rtl/common/third_party`.

FENCE.I dùng whole-D-cache walk theo cấu hình `DcacheFlushOnFenceI=1`. Mỗi line M dirty được ghi từ owner lên LLC chia sẻ qua CCU/HPDcache AXI; sau B response xác nhận LLC đã nhận line, owner có thể chuyển M→E và directory tiếp tục giữ holder. Walk này không yêu cầu LLC ghi ra DRAM. Khi walk xong, invalidate I-cache và fetch pipeline cục bộ của hart đang chạy rồi hoàn tất fence. Nếu B response L1-to-LLC khác OKAY, giữ M/directory holder, gửi ABORT và chờ đủ ACK; sau đó CVA6 phát exception đồng bộ chính xác cause 24 tại PC FENCE.I, đặt physical line base đã căn chỉnh vào `mtval`/`stval`, không retire fence/lệnh sau và không invalidate I-cache/fetch. Việc sửa, kiểm chứng trap path và retry thuộc DEP-021. Đây là thao tác instruction stream cục bộ; các hart khác cần được phần mềm thông báo và tự chạy FENCE.I.
